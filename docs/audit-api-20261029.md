# Compiled API and unit parser audit

A01–A10 are reproduced in `core/tests/audit_api_20261029.rs`. All desired-behavior
tests failed before fixes. These cover different public API contracts; signed,
scientific, and long decimal quantity parsing have independent failure modes.

| ID | Defect |
|---|---|
| A01 | Compiled expressions ignore dimensions of quantity arguments when the parameter uses auto: `x+1 m` called with `2 s` returns3. |
| A02 | Negative math quantity arguments are rejected by the numeric/unit grammar. |
| A03 | Scientific numeric strings are tokenized but rejected by the exact-only number parser. |
| A04 | Finite long decimals are rejected instead of falling back to floating arithmetic like the worksheet parser. |
| A05 | Explicit multiplication after unit division stays in the denominator: `m/s*m` becomes `1/s` rather than `m²/s`. |
| A06 | `clear("x(y)+z(t)")` silently deletes x despite not being a name or function call. |
| A07 | Compiled result-unit conversion can return Some(infinity) rather than none when output overflows. |
| A08 | Unit mismatch diagnostics print encoded lexical binding JSON hex rather than the user's unit names. |
| A09 | Compiling an unresolved function succeeds and yields an unusable snapshot instead of diagnosing the missing definition. |
| A10 | Unit expressions with missing operands (`m/`, `*m`, `m**s`, `m//s`) are silently accepted. |

Fixed A01–A10. Compiled snapshots retain the requested result dimension for
runtime checks when parameter dimensions are supplied only by quantity arguments.
Signed/scientific/long-decimal inputs, output overflow, clear syntax, unit operator
precedence and readable diagnostics have regression coverage. The 13 audit tests
and 13 existing focused API/unit/operator validation tests pass (26 total).
