# Numerical bug audit — 2026-10-29

Ten confirmed bugs in supported operations, reproduced through the worksheet API.
These are independent affected calculations; some share numerical scaling helpers.
Missing or explicitly unsupported features were excluded.

Each expression below uses the numeric result marker `=>`. `#i` is the imported imaginary constant.

| # | Expression | Before | Correct result |
| --- | --- | --- | --- |
| 1 | `pnorm(10^308,-10^308,10^308)` | 1 | Approximately 0.9772498680518208 |
| 2 | `linterp(vec(-10^308,10^308),vec(0,1),0)` | 0 | 0.5 |
| 3 | `stdev(vec(-10^308,0,10^308))` | Finite-range error | `10^308` |
| 4 | `linfit(vec(-10^308,10^308),vec(-1,1))` | Finite-range error | Intercept 0, slope `10^(-308)` |
| 5 | `minimize(x/10^308,x,-10^308,10^308)` | Undefined-objective error | `-10^308` |
| 6 | `odesolve(0,y,t,1,-10^308,10^308)` | Overflow error | 1 |
| 7 | `asin(100000000*#i)` | Real-argument error | `i * asinh(100000000)`; acos also affected |
| 8 | `ln(13*10^307+13*10^307*#i)` | Real-argument error | `ln(1.3e308) + ln(2)/2 + i*pi/4` |
| 9 | `lsolve(mat(10^(-308)),vec(10^(-308)))` | Vector containing 0 | Vector containing 1 |
| 10 | `idft(vec(10^308,10^308))` | Vector containing 0, 0 | Vector containing `10^308`, 0 |

The fixes normalize computations before overflowing differences, sums, or complex
magnitudes are formed. Complex cleanup preserves nonfinite values so failures
cannot silently turn into zero. Regression coverage is in
`core/tests/numerical_stability_audit.rs`, including sign changes and related inputs.

The baseline workspace suite and an expanded core fuzz run (`FUZZ_N=3000`,
`FUZZ_SEED=29102026`) passed before the fixes. This audit is not an exhaustive proof
of correctness; the failures above required targeted floating-point boundary cases.

Four additional issues surfaced when compiling the documentation:

11. `calculate($I/3 =>$ , digits: 2)` rejected all named formatting options,
    despite the documented contract. It now forwards options to the shared worksheet.
12. `defined(kinds: "given")` mutated an outer parameter inside a context block,
    which Typst prohibits. It now normalizes the filter into a local binding.
13. The `compile` reference example omitted its unit imports and resistance
    definition. It now includes those prerequisites.
14. The modifier example read `t` after a solve that does not define variables.
    It now explicitly defines the value before displaying it.

Post-fix Rust workspace validation: 574 passed, 21 ignored, zero failures.
The expanded randomized run also passed after the numerical changes, and the
Typst plugin was rebuilt. The initial full Typst fixture run passed 17/25;
remaining fixture failures include stale expectations that solving implicitly
creates definitions and an old `=` response marker. These have not been counted
as product bugs or silently rewritten to match current behavior.

All documented examples compile after the four additional fixes. The dedicated
Typst regression fixture `tests/bug-audit/test.typ` also compiles, checking
formatting-option forwarding and both string and array definition filters.
